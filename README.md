# 🌸 QQ 群大模型管理工具插件 (`astrbot_plugin_qq_group_admin`)

一款专门为 **AstrBot** 注册原生大模型工具（LLM Tool）的 QQ 群管理与互动插件。无需记忆任何死板的前缀或正则表达式命令，让大模型直接理解群管理或群友的自然语言诉求（如“把小明禁言5分钟”、“把那个打广告的踢出群聊并拉黑”、“撤回某某最近的几条消息”、“把小明刚发的消息设为群精华”、“查一下张三最近什么时候发言”、“清理超过60天未发言且群等级低于10级的潜水成员”、“戳一下某某”、“@新进群的那个让ta看群公告”、“看看群里群等级人数分布”等），并支持自动入群审核和人机验证等。

---

## ✨ 核心特性

1. **大模型原生 17 大 Tool 组合与 @ 成员/@ 全体成员支持**：
   - `ban_group_member`：对指定群成员执行禁言或解除禁言。
   - `kick_group_member`：将指定群成员移除群聊（踢人），支持是否同时拒绝后续加群申请（拉黑/黑名单）。
   - `delete_group_message`：撤回单条或多条指定消息，支持指定单个或多个 ID（用逗号/空格分隔）进行批量撤回，亦支持回复/引用消息时自动识别并撤回。
   - `set_group_essence_message`：设置或取消群精华消息，支持回复/引用消息时自动识别并设为精华/移除精华。
   - `get_group_msg_history`：获取群聊历史消息记录（单次最多可调取 500 条历史记录），协助上下文寻找发言 ID。
   - `set_group_whole_ban`：开启或解除全员禁言（全体禁言）。
   - `set_group_card`：设置或修改指定群成员的群名片/群昵称（支持重置清空名片）。
   - `set_group_special_title`：为指定群成员颁发专属头衔（支持指定有效天数或永久有效，需 Bot 为群主）。
   - `set_group_admin`：设置或取消某位成员的群管理员身份（需 Bot 为群主）。
   - `set_group_name`：修改当前 QQ 群聊的名称。
   - `send_group_notice`：群公告全能工具，支持发布全新群公告、读取群公告列表、删除指定群公告（基于 NapCat 扩展 API `_send_group_notice` / `_get_group_notice` / `_del_group_notice`）。
   - `get_group_info`：获取当前群聊的详细信息（群名称、群主 QQ、当前成员数与容量上限等）。
   - `get_group_member_list`：获取全员列表，支持按关键词（昵称/名片/QQ号/身份）精准搜索与筛选，支持按进群时间、最近发言时间、群等级进行多维度排序（含最后发言时间、入群时间与 LV 群等级标注），支持统计各群等级人数分布（summary_only，遍历全部成员不受 30 人展示截断限制）；列表与关键词搜索默认展示前 30 人，超出时附「… 等共 N 人」总数提示。
   - `get_group_member_info`：查询指定群成员的详细个人资料（精确查看最近发言时间、入群时间、群身份、群等级 LV、专属头衔、禁言状态等）。
   - `kick_inactive_members`：查找或清理长时间未发言的潜水成员（自动跳过群主和管理员，支持结合潜水天数与群等级上限门槛双重筛选，具备二段安全预览确认）。
   - `group_poke`：对指定群成员执行调皮的“戳一戳”（拍一拍/戳一下）动作（也可配合被动监听事件响应用户的戳一戳）。
   - `at_all_members`：请求 @全体成员 操作授权，结合拦截器完成原生高亮合流发送（包含发送者与 Bot 自身双重管理员权限预检）。
   - **智能艾特成员**：支持大模型在自然语言回复中输出 `[at:QQ号]` 自动转换为原生高亮 At 组件（带零宽字符防粘连）。
2. **灵活的权限控制与普通群友授权**：
   - `allow_bot_admin`：**允许** Bot 配置文件中指定的超级管理员使用（默认 `true`）。
   - `allow_group_admin`：**允许**目标群的管理员使用（默认 `true`）。
   - `allow_group_owner`：**允许**目标群的群主使用（默认 `true`）。
   - `enable_at_feature`：**允许** @ 成员功能（默认 `true`）。
   - `enable_poke_reply`：**允许**被戳一戳时自然回复（默认 `true`）。
   - `member_allowed_tools`：允许普通群友调用的功能工具列表（可通过配置面板勾选纯中文工具名如“清理潜水成员”、“查询成员信息”，授权给普通群成员使用）。
3. **安全严密防护、Bot 身份预检与群聊黑名单**：工具被大模型触发时，会在函数底层二次强校验发送者的实际身份与勾选授权列表，防止普通群成员越权使用敏感群管命令；同时在底层加入了针对 Bot 账号自身的管理员/群主身份前置预检，避免因权限不足导致的 API“假成功”现象；并支持群聊黑名单列表拦截，在黑名单中的群聊将完全禁用本插件的所有功能。
4. **等级门槛 + 白词自动同意入群**：监听加群申请事件，按申请人 QQ 等级与入群白词自动处理入群申请——「等级达到门槛时自动同意入群」与「白词命中时自动同意入群」可单独开启（各自独立生效：等级渠道看等级、白词渠道看白词），也可同时开启：配合「入群双重审核」开关可切换为**双重验证**（白词命中且等级达标同时满足才自动同意）或**任一满足即同意**；「等级未达门槛时自动拒绝入群」与「未命中入群白词自动拒绝」是两个独立拒绝开关，配合「拒绝入群双重验证」开关可切换为两个拒绝条件同时满足才拒绝或任一满足即拒绝；未命中自动同意条件时保持默认人工审核流程，黑名单群不生效。
5. **友好的异常反馈**：若 Bot 自身在群内缺乏管理员/群主权限或 API 调用失败，大模型能获得清晰明确的回执说明。
6. **自动入群审核体系（人机验证 + 多群共享的黑名单防护）**：
   - **人机验证**：新人入群后 Bot 自动 @新人 发送随机加减法人机验证题目，限时作答、答错扣减机会，超时或机会用完自动移出群聊；可配置拉黑阈值，达到拉黑阈值自动拉入入群黑名单；关闭「入群人机验证」开关或停用/卸载插件时，进行中的人机验证任务会自动取消（不会残留超时踢人等幽灵任务）。
   - **多群共享的黑名单防护**：入群黑名单按 QQ 号全局记录、跨群共享——黑名单用户申请任意群都会被自动拒绝，通过其他途径偷溜进群也会收到提示并在 10 秒后被移出；配套入群审核管理面板支持手动拉黑/解除、失败次数与剩余次数管理、拉黑即踢（@提示 10 秒后移出 Bot 拥有管理员权限的群聊）。
7. **退群监测提示**：监听群成员退群事件——有人**主动退群**时群内提示「xxx(QQ号) 已主动退群」；被管理员/群主**移出**时提示「xxx(QQ号) 已被 群主yyy / 管理员yyy 移出群聊」（自动识别操作者身份，操作者名字优先显示群昵称/群名片，无则回退 QQ 昵称）；Bot 自己踢人时静默不打扰；可通过「退群提示开关」一键关闭，黑名单群不生效。

## 🚀 大模型工具使用方法与指令范例

插件无需注册任何死板的前缀命令。只要当前发送者满足管理员权限要求，或调用的特定功能已被勾选授权给普通群友使用，在 QQ 群聊中直接对 Bot 提出自然语言要求即可：

### 1. 禁言与解禁（`ban_group_member`）
- **常规禁言**：“把小明禁言 5 分钟” / “给小明套餐半小时”
- **解除禁言**：“把小明放出来” / “解除小明的禁言”

### 2. 踢出群聊（`kick_group_member`）
- **常规踢人**：“把张三踢出群聊” / “把张三移出本群”
- **踢人并拉黑**：“把那个打广告的踢出去，并且拒绝他再申请加群” / “把张三移除群聊并拉黑”

### 3. 撤回消息（`delete_group_message`）
- **引用撤回**：（回复/引用某条违规消息）“把这条消息撤回” / “撤回他刚才发的内容”
- **指定 ID 撤回**：“撤回张三刚才发的那条消息”

### 4. 群精华消息（`set_group_essence_message`）
- **引用设为精华**：（回复/引用某条优质消息）“把这条设为精华” / “设为群精华消息”
- **引用取消精华**：（回复/引用某条已设为精华的消息）“取消精华” / “把这条消息移除群精华”
- **指定 ID 设精华**：“把张三刚才发的那条设为精华”

### 5. 读取历史消息（`get_group_msg_history`）
- **查历史**：“看看群里最近发了什么” / “获取最近 50 条群历史消息”

### 6. 全体禁言（`set_group_whole_ban`）
- **开启全体禁言**：“开启全员禁言” / “开启全体禁言”
- **解除全体禁言**：“解除全员禁言” / “恢复全员发言”

### 7. 修改群名片（`set_group_card`）
- **修改名片**：“把小明的群名片改成小笨蛋”
- **重置名片**：“清空小明的群名片”

### 8. 专属头衔（`set_group_special_title`）
- **设置头衔**：“给张三颁发一个‘群宠’专属头衔”

### 9. 管理员设置（`set_group_admin`）
- **设置管理员**：“把小明设为群管理员”
- **取消管理员**：“取消小明的管理员身份”

### 10. 修改群名称（`set_group_name`）
- **修改群名**：“把群名称改成星穹列车聊天群”

### 11. 群公告全能工具（`send_group_notice`）
- **发布公告**：“发个群公告：今晚 8 点开会，大家准时参加”
- **读取公告**：“看看这个群有哪些公告” / “查一下群公告列表”
- **删除公告**：“把那条『今晚8点开会』的公告删掉” / “删除群公告”

### 12. 获取群信息（`get_group_info`）
- **查群信息**：“看看咱们这个群的信息”

### 13. 获取成员列表与搜索（`get_group_member_list`）
- **查看成员**：“查看群成员列表”
- **按关键词与身份搜索**：“搜一下群里有没有叫小明的” / “看看群里有哪些管理员”
- **按发言/入群/群等级排序**：“看看最新加群的新人是谁” / “查一下群里最近谁发言了” / “看看群里等级最高的是谁” / “查一下群等级最低的人”
- **统计群等级人数分布**：“统计一下这个群 LV.30 有多少人” / “看看群里群等级人数分布” / “这个群各级别分别有多少人”

### 14. 查询单人成员资料与最后发言时间（`get_group_member_info`）
- **查成员详细资料**：“查一下张三最近什么时候发言” / “查询张三的详细群资料”

### 15. 查找与清理潜水成员（`kick_inactive_members`）
- **安全扫描预览**：“查找群里超过 60 天没发言的人” / “看看有哪些人两个月没发言且群等级低于 10 级”
- **确认一键清理**：“确认清理超过 60 天未发言且群等级低于 10 级的潜水成员”

### 16. 戳一戳（`group_poke`）
- **戳一下**：“戳一下小明” / “拍一拍小明”

### 17. @成员与 @ 全体（`at_all_members`）
- **@ 某人**：“去@一下张三，叫他开会” / “@新进群的那个让ta看群公告”
- **@ 全体成员**：“@全体成员 记得今晚 7点看前瞻直播”

## ⚙️ 配置说明

在 AstrBot 管理面板的插件配置页面中，配置项分为四个分组：

### 🛠️ 群聊管理与互动工具

| 配置项 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `allow_bot_admin` | bool | `true` | **允许 Bot 超级管理员**（`admins_id` 列表中的账号）使用管理工具 |
| `allow_group_owner` | bool | `true` | **允许目标群群主使用管理工具**（开启后，目标群的群主可让 Bot 执行群管理指令） |
| `allow_group_admin` | bool | `true` | **允许目标群管理员使用管理工具**（开启后，目标群的管理员可让 Bot 执行群管理指令） |
| `enable_at_feature` | bool | `true` | **允许 @ 成员功能**（开启后大模型可在回复中 @ 成员/全体成员，@全体成员需对应权限） |
| `enable_poke_reply` | bool | `true` | **允许被戳一戳时自然回复**（开启后当有人戳 Bot 时按角色性格回应） |
| `enable_group_decrease_notice` | bool | `true` | **退群提示开关**（开启后，有人退群时 Bot 会在群内提示「谁主动退群了」或「谁被管理员/群主移出群聊」；黑名单群不生效） |
| `member_allowed_tools` | list | `["读取历史消息", "获取群信息", "获取全员列表", "查询成员信息", "戳一戳"]` | **允许普通群友使用的功能工具**（勾选的功能工具将允许普通群友直接指挥 Bot 调用使用） |

### 🤖 自动同意入群工具

| 配置项 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `auto_accept_group_request` | bool | `false` | **等级达到门槛时自动同意入群**（等级渠道。开启后 Bot 按等级门槛自动同意加群申请；要求 Bot 具备群管理员权限，黑名单群不生效） |
| `auto_reject_below_level` | bool | `false` | **等级未达门槛时自动拒绝入群**（独立功能，即使等级自动同意未开启也能生效。开启后，申请人 QQ 等级低于 `auto_accept_group_level` 门槛时 Bot 自动拒绝入群；关闭则不拦截，等级未达标的申请仍可交由白词渠道/等级渠道判断。需等级门槛大于 `0`） |
| `auto_accept_group_level` | int | `0` | **QQ 等级门槛**（填 `0` 代表不限制等级；填其他数值如 `30` 代表自动同意或拒绝入群的 QQ 等级门槛） |
| `auto_accept_whitelist` | bool | `false` | **白词命中时自动同意入群**（白词渠道。开启后，申请人填写的入群验证信息包含任一白词时自动同意入群） |
| `auto_reject_whitelist_miss` | bool | `false` | **未命中入群白词时自动拒绝入群**（独立功能，即使自动同意未开启也能生效。开启后，申请人填写的入群验证信息未包含任何入群白词时 Bot 自动拒绝入群；关闭则保持人工审核。需先在入群白词列表中配置白词） |
| `auto_accept_group_whitelist` | list | `[]` | **白词列表**（入群验证信息包含或不含任一白词将自动同意或拒绝入群；留空表示不启用白词功能） |
| `auto_accept_dual_verify` | bool | `false` | **入群双重审核**（仅对「等级达到门槛时自动同意入群」与「白词命中时自动同意入群」同时开启的场景生效：开启后需等级达标且白词命中同时满足才自动同意（AND）；关闭则满足其一即可（OR）） |
| `auto_reject_dual_verify` | bool | `false` | **拒绝入群双重验证**（仅对「等级未达门槛时自动拒绝入群」与「未命中入群白词时自动拒绝入群」同时开启的场景生效：开启后需等级未达标且白词未命中同时满足才自动拒绝（AND）；关闭则满足其一即拒绝（OR）） |

### 🛡️ 入群人机验证

| 配置项 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `enable_join_verify` | bool | `false` | **入群人机验证开关**（开启后，新人入群时 Bot 将 @新人 发送随机加减法题目进行人机验证） |
| `join_verify_timeout` | int | `180` | **验证超时时间（秒）**（新人入群后在此时间内未回复正确答案将被移出群聊） |
| `join_verify_max_attempts` | int | `3` | **最大错误次数**（回复错误达到此次数后将被移出群聊） |
| `join_verify_max_failures` | int | `0` | **人机验证累计失败次数上限（拉黑阈值）**（每次验证未通过消耗 1 次；累计达到该次数后自动将用户拉入入群黑名单，后续申请入群将被自动拒绝。`0` = 不限制） |

### 🚫 群聊黑名单

| 配置项 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `blacklisted_groups` | list | `[]` | **黑名单群聊列表**（填入群号如 `12345678`；在黑名单列表中的群将完全无法使用本插件的任何功能，包括群管工具、@功能与戳一戳响应） |

## ❓ 常见问题 (FAQ)

- **为什么在插件里勾选开启了“群主”、“群管理员”权限，但他们依然无法调用插件？**
  - 请检查：是否在 AstrBot WebUI 的函数工具权限配置里把对应工具单独设为需要「管理员」权限

- **为什么提示“Bot 自身在群中缺乏管理员权限”？**
  - 实际在 QQ 服务端执行禁言、踢人、撤回、设置精华、修改群名片等动作的是 **Bot 账号自身**。因此，请确保 Bot 账号在当前 QQ 群中拥有**管理员**或**群主**身份。

- **开启了自动同意入群但没生效？**
  - **Bot 在群内无管理员权限**：自动同意入群需要 Bot 账号在该群内执行加群审批操作，请确保 Bot 拥有该群的管理员或群主身份。
  - **该群在黑名单群列表中**：黑名单群中的群聊将完全禁用本插件的所有功能（含自动入群审核），将该群从 `blacklisted_groups` 配置中移除后即可恢复生效。

- **人机验证时回复带 @ 或引用消息会被识别吗？**
  - 会正常识别——人机验证只提取消息中的纯文本段进行判定，即使回复时 @ 了 Bot 或引用了消息也能正常识别。
  - 且**待验证用户**验证期间的消息不会触发 Bot 的 LLM 回复（只有待验证用户的消息会被拦截处理，其他群成员的消息完全不受影响）。
